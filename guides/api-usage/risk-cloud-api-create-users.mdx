The Create User endpoint can be helpful for integrations that automate the onboarding of new
colleagues or teams to the Risk Cloud. To create Users in your environment via the Risk Cloud
API, assemble the JSON of the User and submit it in a `POST` request.

## Authentication

Prior to any interaction with the Risk Cloud API you'll need an Access Token for the
`Authorization` header — see [Authentication](/guides/api-usage/authentication).

Creating a User via the Risk Cloud API requires an Access Token from an Admin Primary account.

## Usage

Creating a User via the Risk Cloud API is a two-step process:

1. Configure the User in JSON.
2. Create the User via a request.

### 1. Configure the User in JSON

```json
{
  "active": true,
  "status": "Active",
  "tier": "SECONDARY",
  "valueType": "User",
  "sendEmail": false,
  "email": "email@your-company.com",
  "first": "FirstName",
  "last": "LastName",
  "company": "Your Company"
}
```

Adjust `tier`, `sendEmail`, `email`, `first`, `last`, and `company` to the User you're creating.

If `sendEmail` is `true`, the system sends an automatic Welcome Message after the User is
created.

`tier` designates the User's access tier:

| Value | Description |
|---|---|
| `PRIMARY` | Users who have access to the Build section of the app (typically Admin users). |
| `SECONDARY` | Users without access to the Build section (typically end-users). |
| `LIMITED` | Secondary users who only use the platform infrequently (typically end-users performing quarterly or annual tasks). |

### 2. Create the User via a request

Once the JSON for the User has been assembled, submit it to:

```
POST https://your-company.logicgate.com/api/v1/users
```

```bash
curl --request POST 'https://your-company.logicgate.com/api/v1/users' \
--header 'Content-Type: application/json' \
--header 'Authorization: Bearer {ACCESS_TOKEN}' \
--data-raw '{
"active": true,
"status": "Active",
"tier": "SECONDARY",
"valueType": "User",
"sendEmail": false,
"email": "email@your-company.com",
"first": "FirstName",
"last": "LastName",
"company": "Your Company"
}'
```

If successful, the User is created and the response contains the new User's information,
including the User ID, which can be used for future API requests.
